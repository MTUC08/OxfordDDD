# 1. What is the purpose of software design and how is it different from coding?

The purpose of software design is to create software that is intuitive to use and (ideally) easy to maintain.
It is different than coding in the same way that writing a note is different from writing an essay or story.
The design is to shape the code and add structure, in the same way an outline guides notes into the form of an essay.

# 2. What is "good" design and "bad" design? How can you tell them apart?

Good design should be easy to understand, use, maintain, and expand. Bad design would be the opposite,
something difficult to understand or use. Often, you can spot good designs by how seamless the user experience is.
Conversely, a bad design is easily spotted by how miserable the experience is.

# 3. If you are beginning a new project, how do you start with the design?

When beginning a new project, I begin by gathering user requirements.
What are they aiming to build? When do they want it done? What are some likely future feature additions?
I then choose tools and components that will best fit and balance the immediate and future needs of the user
against the maintenance experience for the developer.

# 4. What is the hardest part of design. What is most likely to make a design fail?

The hardest part of design is ensuring that user requirements are properly captured and accounted for.
As requirements come from users, they are oft to change, and it can be
hard to identify when to stop designing and when to begin building.
If too much time is spent, we run the risk of over-designing the solution, but if not enough is spent,
we are likely to miss key requirements that will impact the longevity of the design/solution.

A design is most likely to fail when they fail to address a user requirement. Ultimately, designs are used and tested
by users. If a user chooses not to use the solution, then the design has failed.
